# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**NZ Traffic** — a native SwiftUI macOS app for live New Zealand traffic: cameras, road events, VMS signs, travel times (journeys, roadside travel-time boards, Auckland motorway congestion), a seven-layer map, a watchlist with closure notifications, a menu-bar extra and a Dock badge for active closures. Deployment target **macOS 27.0**, Apple silicon (`arm64`) only, **Swift 6 language mode**. No package manager, no analytics, no backend — just `swiftc` against the macOS SDK plus an Xcode project that points at the same sources. Don't add `#available` / `@available` gates for anything macOS 27 already has.

### Identity

- Product name "NZ Traffic" (`AppIdentity.productName`), executable `NZTraffic`, bundle ID `io.github.siliconesessions.nztraffic`, copyright holder "siliconesessions". The product must not be named after the agency (NZTA terms clause 7(b)); "NZTA" appears only where it credits the data source.
- Data is credited to **"NZ Transport Agency Waka Kotahi (NZTA)"** under CC BY 4.0, EV data to "EV Roam, NZ Transport Agency Waka Kotahi" (CC BY 4.0). All credit/notice wording lives in `AppCredits` (`AppIdentity.swift`) and is shared by About, Help, the About panel and the Road Events caption. The "notable events" notice (terms clause 3(c)) and "not affiliated with or endorsed by NZTA" must stay visible.
- UserDefaults keys keep their historic `nzta.*` names — never rename them.
- Version 3.0 renamed the app from "NZTA Traffic" (bundle ID `com.local.NZTATrafficMac`). `LegacyMigration.runAtLaunch()` (first thing in `NZTrafficApp.init`) copies the old defaults domain into the new one once (never overwriting, never deleting the old domain) and moves `Application Support/NZTATraffic` to `…/NZTraffic`. Its decisions are pure functions over in-memory values so tests never touch `~/Library`.
- `Resources/Info.plist` is the **single source of truth** for `CFBundleShortVersionString` and `CFBundleVersion` — bump both there. The pbxproj deliberately has no `MARKETING_VERSION` / `CURRENT_PROJECT_VERSION`, so don't edit the version in Xcode's General tab.
- The API User-Agent is `NZTraffic/<version> (macOS; +https://github.com/siliconesessions/NZTA-Traffic)` (`AppIdentity.userAgent`).

## Build / run

Two parallel build paths exist; both must keep working:

- **Xcode**: `NZTraffic.xcodeproj` (objectVersion 77), shared scheme `NZ Traffic`. `Sources/` is a **file-system synchronized folder** attached to the app target, so any `.swift` file dropped into `Sources/` joins the Xcode build automatically — no pbxproj edit needed. Keep `Sources/` **flat and Swift-only**: `build_app.sh` globs `Sources/*.swift` (non-recursive, so a subfolder would be missed by the shell build) and the synchronized folder would bundle any non-source file as a resource. CI enforces this. `Resources/Info.plist`, `Resources/AppIcon.icon` (Icon Composer icon, compiled by actool; `AppIcon.png` is its 1024 px source) are explicit references; `Tests/` is a synchronized folder with **no** target membership (navigator only), and `CLAUDE.md` / `README.md` / the scripts are navigator-only file references. If you ever do hand-edit `project.pbxproj`, grep the whole file first so new object IDs can't collide with existing ones (a collision crashes xcodebuild).
- **Shell**: `./build_app.sh` — invokes `swiftc` directly (no SwiftPM), compiles the icon with `actool`, and produces `build/NZ Traffic.app` plus `build/NZ Traffic.app.dSYM`. `arm64` only (macOS 27 is Apple-silicon only; CI asserts it). `ARCHS` still takes a space-separated list for a lipo'd binary + merged dSYM, but that is unsupported. The executable's debug map is stripped (`strip -S`) after the dSYM is made. `MACOSX_DEPLOYMENT_TARGET` overrides the min OS (default `27.0`) and is also stamped into the bundled `LSMinimumSystemVersion` (Info.plist holds `$(MACOSX_DEPLOYMENT_TARGET)`, which Xcode expands), so the Mach-O `minos` and the plist always agree.

The two paths are kept equivalent to the Xcode Release configuration: Swift 6 language mode + `MemberImportVisibility` upcoming feature, `-O` with whole-module optimisation, debug info → dSYM, dead-code stripping, deployment target 27.0, `arm64`, and an ad-hoc signature **with the hardened runtime** (`codesign --options runtime --sign -`). Remaining differences: Xcode's Info.plist processing adds the `DT*` / `BuildMachineOSBuild` / `CFBundleSupportedPlatforms` keys and uses explicit module builds; the DMG packages the `build_app.sh` output. If you change a compiler flag or deployment setting, change it in `build_app.sh`, `run_tests.sh` **and** the pbxproj.

Concurrency settings are deliberate: Swift 6 strict checking is on, but **Approachable Concurrency is off** (`SWIFT_APPROACHABLE_CONCURRENCY = NO`) and default actor isolation stays `nonisolated` (no `SWIFT_DEFAULT_ACTOR_ISOLATION`). The async entry points in `TrafficAPIService` are `@concurrent` so decoding stays off the main actor even if that changes; keep new async fetch/decode helpers `@concurrent` too.

CLI release build:

```sh
xcodebuild -project NZTraffic.xcodeproj -scheme "NZ Traffic" -configuration Release -destination 'generic/platform=macOS' build
```

Run the built app: `open "build/NZ Traffic.app"`.

### Release / distribution

Distribution is **ad-hoc signed DMGs attached to GitHub Releases** (no Developer ID, no notarization — an ad-hoc signature can't be notarized, so users go through Gatekeeper's System Settings › Privacy & Security › Open Anyway; the wording lives in `AppCredits.gatekeeperSteps` and the README). `./package_dmg.sh` runs `./run_tests.sh` (unless `SKIP_TESTS=1`), rebuilds via `build_app.sh`, stages the app with an `Applications` symlink, checks the staged signature (including the hardened-runtime flag), creates a ULMO (LZMA) DMG, runs `hdiutil verify`, and writes `dist/NZ-Traffic-<version>-macOS-arm64.dmg` plus `….dmg.sha256` and a matching `…dSYM.zip` for symbolicating crash reports. The arch label comes from the built binary (a universal override is labelled `universal`); the version comes from Info.plist with no fallback, and an existing DMG of the same version is only replaced with `OVERWRITE=1`. `dist/` is git-ignored — never commit DMGs.

### CI

`.github/workflows/ci.yml` runs on GitHub's `xcode-27` runner image (macOS 27, arm64): it selects the newest Xcode 27.x (failing clearly if none or if the SDK is older than 27), checks `Sources/` is flat Swift-only and every `Tests/*.swift` is in `run_tests.sh`, then runs `./run_tests.sh`, `./build_app.sh` and the xcodebuild Release build (failing on any Swift warning from `Sources/`), and checks the shell-built bundle's signature, hardened runtime and `LSMinimumSystemVersion`.

### Tests

`./run_tests.sh` compiles the Foundation-level sources — `Models.swift`, `AppIdentity.swift`, `RefreshPolicy.swift`, `OfflineCache.swift`, `TrafficAPIService.swift`, `TrafficStore.swift`, `ViewLogic.swift`, `MapClustering.swift` and `Watchlist.swift` — plus the listed `Tests/*.swift` into a standalone executable (no SwiftPM/XCTest) and runs it **three times**: in the Mac's time zone, `TZ=UTC` and `TZ=America/Los_Angeles`, so date code that forgets to pin NZ time fails even on a Mac set to NZ time. It exits non-zero on any failure, can be run from any directory, uses the same Swift 6 / `MemberImportVisibility` flags as the app, always builds for the host architecture (`ARCHS` is ignored; `TEST_ARCH` forces a slice), runs with `CFFIXED_USER_HOME=build/test-home`, and prints each test group name to stderr so a trap is easy to locate.

- Coverage: model decoding and the lossy decoders, coordinate validation, WKT parsing, VMS formatting, NZ date parsing/formatting, highway keys and `matches(region:highway:search:)`, event status, journey geometry and direction summaries, TIM boards, EV status, congestion XML, the refresh policy (intervals, freshness banner, Dock badge, `SingleFlight`), the API client (retry, rest/5→rest/4 fallback, timeouts), `OfflineCache` and `TrafficStore` end to end against `StubURLProtocol` (`Tests/StubNetwork.swift`, an in-process route table), view logic, map clustering, the watchlist and closure notifications, identity/migration, and the data-source list / credits (`CreditsTests.swift`).
- `Tests/Fixtures/` holds trimmed **verbatim** records from the live feeds (cameras, events, vms, journeys, tim, regions, congestion.xml, ev.geojson), found via `NZ_TRAFFIC_FIXTURES` (`FixtureTests.swift`). Prefer adding real-payload fixtures over hand-written JSON when a feed's shape matters.
- Tests must never read or write the real user's defaults or Application Support — use pure in-memory seams (e.g. `DiagnosticsReport.collectPreferences(from: [String: Any])`, `diagnosticsReport(preferences:)`, `LegacyMigration`'s pure planners), `OfflineCache(directory:)` on a temporary folder, and `TrafficStore(service:cache:imageCache: nil, monitorsNetwork: false, reconnectDelay:clock:)`. Don't call `OfflineCache.defaultDirectory` in tests.
- Keep the compiled-for-tests files free of `SwiftUI`/`AppKit` imports (Foundation, CoreLocation, CryptoKit, Network, Observation and Synchronization are fine). Pure logic a view needs goes in `ViewLogic.swift` (or another Foundation-only file) so it can be tested.
- A new test file must be added to the `swiftc` list in `run_tests.sh` and its entry point called from `Tests/main.swift`; a new Foundation-only source the tests need must be added there too. New decoded fields and parsing logic get a case in the tests; run `./run_tests.sh` before committing model changes.

### Data sources

All requests go straight from the app to two hosts (plus Apple MapKit tiles and camera JPEGs on trafficnz.info). `TrafficAPIService.dataSources` is the canonical list:

- **trafficnz.info REST v5** (`https://trafficnz.info/service/traffic/rest/5`, JSON, undocumented superset of v4): `/cameras/all`, `/events/all/10`, `/signs/vms/all`, `/journeys/all/10`, `/signs/tim/all`, `/regions/all/10`. A 404/410 retries that path once on the documented **rest/4** and remembers it for the session (`APIVersionFallback`, reported in diagnostics); v5-only fields are optional in the models.
- **trafficnz.info traffic-conditions REST 2** (`/service/traffic-conditions/rest/2`, **XML**): Auckland motorway congestion, parsed by `CongestionXMLParser`. No v4 fallback.
- **services.arcgis.com** (NZTA's EV Roam layer on ArcGIS Online, **GeoJSON**): EV charging stations. Fetched once per launch and re-fetched after an hour (`AutoRefreshPolicy.shouldRefetchEVChargers`), not every refresh.

The session fails fast (`waitsForConnectivity = false`, 30 s idle / 90 s resource timeout; journeys gets a 60 s request timeout because the server spends 14–17 s on it). `RetryPolicy` retries only transient failures (`isRetriable`: 5xx and transport errors other than unreachable-host / timeout / offline codes); URLSession cancellation surfaces as `CancellationError`, never as a network error. Every section fetch returns a `SectionFetch` (decoded value, raw bytes, `ContentDigest`, skipped-entry count) and has a `@concurrent` `…Result()` variant that converts throws to `Result` so one failure never kills the other sections.

### Data flow and filtering

The App owns the single `TrafficStore` and passes it to `ContentView(store:)`, `MenuBarContent`, `SettingsView` and the commands — never create a second store in a view. Filtering and sorting live in the store and models, not the views:

- Shared filters: Region is `@SceneStorage("nzta.scene.region")`; Highway and Search are debounced in `GlobalFilterToolbar`. `store.filtered*(region:highway:search:)` apply them; `store.scoped*` add each tab's chips (`@AppStorage`: camera status, event impact/planned/resolved, flow, hide empty VMS, hide blank TIM) and the Watching filter. When extending filters, add the predicate to the shared `matches(region:highway:search:)` (`TrafficFilterable` in `Models.swift`) and the store accessor, and add any new input to `FilterKey` so the memo stays correct.
- **Region** filters by NZTA's raw tag (`matchesRegion`); labels show `regionDisplayName` (Manawatū-Whanganui, Hawke’s Bay, Bay of Plenty) — display only, never as a tag or key.
- **Highway** matches whole highways, not substrings: `canonicalHighwayKey` maps "SH1" / "SH 1" / "State Highway 1" / "01N" / "SH1N" / "1" to "1" (spurs such as "1B" / "20A" stay distinct), and each model precomputes `highwayKeys` at decode time from its structured fields plus "SH n" mentions in its own name/location text. A non-highway query falls back to a whole-word match on `highwayHaystack`. Search is a folded substring match (diacritics and apostrophes ignored).
- **Road event status** is parsed into `EventStatus` (active / scheduled / resolved / unknown-raw; unknown counts as active). Only `isActiveClosure` feeds the Dock badge, the menu bar "Active closures" and the red map pins; Scheduled events show as "Upcoming"; Resolved events are hidden everywhere unless `@AppStorage("nzta.showResolvedEvents")` (or the Road Events "Resolved" chip) is on.
- **Journeys** show one line per direction, labelled by leg endpoints (`summarizeJourneyDirections`, `journeyLegEndpoints`).
- **Map**: the map tab renders the selected `TrafficMapLayer` from the same filtered slices. Coordinates come from each model's `mapCoordinate` (or WKT parts for lines); features without one are counted as off-map (`MapCounts.unmapped` in `Views.swift`).
- **Watchlist / notifications**: `store.watchlist` (loaded and saved by `AppController`) marks watched items; after each live events refresh the store finds new active closures on watched highways/journeys (`WatchedClosureTracker`; closures already present at launch are not announced) and calls `onNewWatchedClosures`, which `ClosureNotifier` posts if `ClosureNotificationSettings` allows. A notification click opens Road Events via `AppNavigator`.

### Refresh model

Refreshing belongs to the store and the App, never to a window, so it keeps running (and the menu bar and Dock badge stay current) with the main window closed.

- **Launch:** `AppController.start()` → `store.start()` marks every section loading, primes empty sections from the offline cache, then calls `loadAllData()`. `ContentView.task` only calls `store.refreshIfStale(maxAge:)` (joins the launch load; refreshes a reopened window whose data is over 2 minutes old).
- **Single flight:** `loadAllData(bustImageCache:)` runs one refresh at a time (`SingleFlight`); overlapping callers — ⌘R, the menu bar's Refresh Now, an auto tick, Retry, a reconnect, the window reappearing — join it, and a joining explicit refresh "upgrades" it to fresh camera images. Each section also loads single-flight (`loadSection`), which owns that section's loading flag. Don't add a second path that fetches a section directly; per-section Retry is `store.reload(_:)`, the EV layer's is `reloadEVChargers()`.
- **Sections land independently:** each section is applied the moment its own fetch completes. `isRefreshing` covers `DataSection.refreshedTogether` (cameras, events, VMS, TIM, congestion); journeys loads alongside with only its own loading flag; regions are fetch-once and EV chargers hourly.
- **Unchanged feeds:** the JSON is sent no-store and uncompressed (no HTTP revalidation is possible), so every refresh downloads it; when a section's bytes match what's on screen (`ContentDigest`), the array isn't reassigned, its filter memo is kept and the cache file isn't rewritten.
- **Auto-refresh:** `nzta.autoRefreshEnabled` / `nzta.refreshIntervalSeconds` (60–600 s) reach `store.configureAutoRefresh` only through `AppController` — don't reschedule from views. Ticks count from the start of the last refresh of any kind; while the app is inactive with no window visible the interval backs off ×3 (max 15 minutes), and a refresh that fell due meanwhile runs as soon as the app is active again.
- **Failures:** a cancelled load is not an error. Offline (`NWPathMonitor`), no request is made; each section gets an offline error and keeps what it shows. Coming back online after a failure, or with saved data on screen, triggers one debounced reload. `lastUpdated` is stamped only by a successful live fetch of a cacheable section (the ones the banner covers), and header/banner ages re-render every 30 s (`TimelineView`). Errors are per section (`store.errors[.cameras]` etc.), rendered by `ErrorBanner` with Retry inside each tab via `store.displayedError(for:)`, which hides the offline error for a section that still has data (the offline banner covers it); a failed fetch **keeps the section's last-known-good data**.
- **Camera images:** `CameraImage` (`Cards.swift`) loads through `URLSession.shared` / the bounded `URLCache`. When the cameras section refreshes, `cameraImageGeneration` bumps (at most every 30 s) and on-screen images re-request the same URL with `.reloadRevalidatingCacheData` — the JPEGs support ETag/304 — keeping the old frame until the new one arrives. Image URLs carry `?t=\(store.imageCacheToken)`, which starts at 0 (cached images survive relaunches) and changes only on an explicit refresh. Only the camera JPEGs revalidate — the traffic JSON is `no-store`.

### Offline cache (deliberate exception to "no caching layer")

The four cacheable sections (cameras / events / vms / journeys) are persisted for offline use:

- The store persists the **raw JSON bytes** from `SectionFetch` (not re-encoded models — the models have derived stored fields and `CodingKeys` that are a strict subset, so they don't round-trip via `Encodable`). On replay the bytes go back through the same payload wrappers (`decodeCached*`), preserving every derived field.
- `OfflineCache` (an `actor`) does all file IO off the main actor: one `<section>.json` per section under `~/Library/Application Support/NZTraffic/OfflineCache/` (`AppCredits.offlineCachePath`, stated in About/Help). A write whose bytes match the file's digest only refreshes its modification date (when the data was last confirmed). A changed section is rewritten at most every 10 minutes (`minimumRewriteInterval`); newer bytes wait in the actor (and `read` serves them) until then, or until `flush()` — run when the app resigns active and before it quits. Dates come from the cache's injectable clock. Every operation is best-effort.
- `store.start()` primes empty sections from disk (ended events are left out of a replay). On a fetch failure a section keeps what it shows and falls back to the cached copy only if it has nothing; on success it overwrites memory and disk. `savedSections` / `savedDates` track saved data.
- `store.freshnessBanner` drives the `OfflineBanner`: *offline*, *couldn't reach NZTA* (only when a live fetch failed), or *showing saved data … updating…* during a launch's live load — dated by the **oldest** data shown. The Dock badge gets a "?" and the menu bar says "(saved data)" when the closure count comes from saved or failed events.
- Escape hatches: Settings › Clear Offline Cache and Help › Clear Offline Cache… delete the files and the image `URLCache`, then reload. `LaunchGuard` discards the saved copy at launch if the previous launch died before its first refresh finished.

## Conventions worth knowing

- Data comes only from the hosts under "Data sources" — no proxy, no auth, no other backend. If you add a feed, add it to `TrafficAPIService.dataSources` (About/Help/the About panel pick it up) and check its licence/attribution. The one persistence exception is the offline cache; don't add other caching layers without reason.
- VMS message strings arrive with embedded display-control tokens; always run them through `formatVMSMessage` before showing.
- String/number fields from the API can be either type or absent — go through `decodeLossyString` / `decodeLossyDouble` / `decodeLossyInt` and `cleanText`, not raw `decode` calls.
- User-facing text is NZ English ("colour", "grey", "behaviour", "licence" as a noun), uses macrons in names we control, and names the agency "NZ Transport Agency Waka Kotahi". Help and About must describe only features, labels and shortcuts that exist (⌘1–6 tabs, ⌘F, ⌘E, ⌘R, ⌘?, ⌘,, arrow keys / Return / Space / Esc on cards).
- Keep large `body` properties split into computed subviews so the type checker stays fast.
